    Exposure#

    The exposure module links a building inventory to the CHEERSafe damage model. It maps user attributes onto the structural archetype M and the resistance configuration C, assigns per-event wind and flood intensities from hazard control points to building centroids, converts them to the package's continuous hazard IDs (Wind_Tr, Flood_Tr), assigns zone ids and writes the STARR-compatible export consumed by Loss Estimation.

    Archetype Assignment#

    archetype #

    Structural archetype (M) and resistance-configuration (C) assignment.

    M (1-8) follows Peng (2013, Table 3.1): number of stories, hip versus gable roof and garage presence. C (1-192) is one row of the package's ComponentCombination_All.json table, sampled per building from the product of six component-state distributions that depend on the construction period and the distance to the coast (Peng 2013, Tables 3.6 and 3.7). The rule tables and the archetype encoding reproduce the verified Eastern North Carolina scripts; the sampling is seeded through :class:cheersafe.tools.Sampling.

    Base Classes#

    base #

    Base dataclasses and loaders for the exposure module.

    InventorySchema describes how a user inventory maps onto the attributes the archetype rules need. BaseExposure owns every input of the exposure workflow: the inventory layer, the per-event hazard control-point layers, the optional zone layer and the package's discrete hazard and component tables. Subclasses add the archetype, hazard-mapping and export calculations.

    Hazard Mapping#

    hazard_mapping #

    Hazard-to-building mapping and hazard-ID transformation.

    Per-event wind speeds (m/s) and flood depths (m) at hazard control points are assigned to building centroids with a nearest-neighbour or inverse-distance scheme, converted to mph and inches, and interpolated onto the package's discrete hazard IDs (WindSpeed.json and FloodDepth.json). The resulting Wind_Tr and Flood_Tr values are continuous, 1-based IDs; how they are rounded onto lookup-table bins is decided later by the loss-estimation module.

    The module also exposes grid helpers used by the Eastern North Carolina figure notebook: cell indexing on the 1 km control-point grid and probability-weighted hazard summaries.

    make_damage_library staticmethod #

    make_damage_library(
    keys: Sequence[Tuple[int, int]] = (
        (1, 1),
        (2, 101),
        (8, 192),
    ),
    n_wind: int = 25,
    n_flood: int = 136,
    n_damage_states: int = 50,
    seed: Optional[int] = None,
    unnormalized_rows: int = 1,
) -> Dict[Tuple[int, int], ndarray]

    Generate damage-state probability tensors for selected (m, c) pairs.

    Each tensor has shape (n_wind, n_flood, n_damage_states). Rows are discretized bell-shaped distributions whose centre rises monotonically with wind and flood, the zero-hazard row is a point mass on the first damage state, and a configurable number of rows is scaled by 0.9 so consumers can exercise their non-normalized-row warning.

    Parameters:

    Name Type Description Default
    keys Sequence[Tuple[int, int]]

    (m, c) pairs to generate.

    		 ((1, 1), (2, 101), (8, 192))
    n_wind int

    Number of wind IDs.

    		 25
    n_flood int

    Number of flood IDs.

    		 136
    n_damage_states int

    Number of damage states.

    		 50
    seed Optional[int]

    Seed for the per-key random streams.

    		 None
    unnormalized_rows int

    Number of rows whose probabilities are scaled by 0.9, assigned to the keys in order starting from the highest hazard row.

    		 1
    Outputs

    None beyond the returned value.

    Returns:

    Type Description
    Dict[Tuple[int, int], ndarray]

    Dict[Tuple[int, int], np.ndarray]: Float32 probability tensors keyed by (m, c).

    make_inventory staticmethod #

    make_inventory(
    n: int = 40,
    seed: Optional[int] = None,
    crs: str = GRID_CRS,
    origin: Tuple[float, float] = GRID_ORIGIN,
    extent_cells: Tuple[int, int] = (3, 3),
    include_edge_cases: bool = True,
    spread_full_window: bool = False,
) -> GeoDataFrame

    Generate a building inventory in the demo-inventory schema.

    Regular rows are wood-frame single-family dwellings with 10 m square footprints placed inside the hazard control-point bounding box and, by default, inside the zones returned by :meth:make_zones (which caps the x extent at 1.5 km); spread_full_window places them across the whole control-point window instead, for map-style examples. Year built spans 1950-2020 so all three construction periods occur, and coastal distance spans both sides of the 2-mile threshold. Contents value is half the structure value, as in the frozen source export.

    seed Optional[int]

    		 GRID_CRS

    Lower-left control point of the hazard grid.

    		 GRID_ORIGIN
    extent_cells Tuple[int, int]

    Number of control points along x and y.

    Spread regular buildings over the full control-point window rather than the zone-safe 1.5 km strip.
